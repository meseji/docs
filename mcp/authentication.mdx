Every MCP interaction is strictly scoped to the authenticated user and organization. Cross-organization access is blocked at the gateway level.

## Authentication Methods

<Tabs>
  <Tab title="1. API Token (Recommended for IDEs & CLIs)">
    Pass your workspace API token in the `Authorization` header:

    ```http
    Authorization: Bearer mk_live_abcdef1234567890
    ```

    - Tokens can be created, inspected, and revoked anytime from **Dashboard → Settings → API Tokens**.
    - Token requests inherit the organization workspace and permissions assigned to the token creator.
  </Tab>
  <Tab title="2. OAuth 2.0 PKCE (For AI Web Clients)">
    Meseji MCP implements RFC 7591 Dynamic Client Registration and RFC 9728 discovery:

    - **Resource Discovery:** `GET /.well-known/oauth-protected-resource/api/mcp`
    - **Authorization Server:** `GET /.well-known/oauth-authorization-server`
    - **Authorization Code Flow with PKCE** (`S256`).

    When an unauthenticated request hits `/api/mcp`, the server returns a `401 Unauthorized` challenge with the `WWW-Authenticate` header pointing to the metadata discovery endpoint.
  </Tab>
</Tabs>

## Managing and Revoking AI Connections

Users can review connected AI clients and revoke active sessions directly:

```http
# List active AI client connections
GET /api/mcp/connections

# Disconnect / revoke specific AI client
DELETE /api/mcp/connections/{clientId}
```
